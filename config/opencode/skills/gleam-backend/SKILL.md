# Gleam Backend Project Guidelines

## Project Philosophy

This project follows a **type-safe functional approach** on the BEAM. We leverage Gleam's static typing to catch errors at compile time, use the `Result` type for explicit error handling, and embrace immutability. Code should be explicit, well-typed, and leverage BEAM's fault tolerance.

### Project Tiers

Gleam's lightweight syntax and BEAM's concurrency model scale across project sizes:

| Tier | Description | Architecture |
|------|-------------|--------------|
|**Tier 1**| Scripts, microservices, < 5 endpoints| Flat structure, handlers call DB directly, minimal abstraction |
|**Tier 2**| Standard REST APIs, medium complexity| Layered architecture (handlers -> services -> repos), type-safe SQL |
|**Tier 3**| Real-time systems, complex domains| Actor supervision trees, event sourcing, CQRS, hot code reloading |

> **Rule:** Start with Tier 1, refactor to Tier 2 when you have >5 domains, escalate to Tier 3 when you need soft real-time guarantees, persistent GenServer state, or complex supervision strategies.

### Functional Philosophy

"Explicit error handling" means functions declare what can go wrong via `Result` types, not that we avoid errors. We use the type system to make failure states representable and force handling at appropriate boundaries. Embrace pipelines (`|>`) for data flow, actors for stateful processes, and pattern matching for control flow.

## Layer Responsibilities

| Layer | Does | Does NOT | Error Handling |
|-------|------|----------|----------------|
| **Handlers** | Parse HTTP, call service, format JSON responses | Business logic, DB queries | Map service errors -> HTTP status codes |
| **Services** | Business rules, transactions, orchestrate repos | HTTP concerns, raw SQL | Return domain errors (UserError, etc.) |
| **Repositories** | Execute SQL, map to types | Business logic, HTTP concerns | Translate DB errors -> domain errors |

## Naming Conventions

| Type | Convention | Example |
|------|------------|---------|
| **Files** | snake_case | `user_handler.gleam`, `blood_type.gleam` |
| **Modules** | snake_case (path) | `app/handlers/user_handler` |
| **Types** | PascalCase | `User`, `CreateDonationError` |
| **Functions** | snake_case | `get_by_id`, `create_user` |
| **Variables** | snake_case | `user_id`, `donation_count` |
| **Constants** | snake_case | `max_retries`, `default_page_size` |
| **Type parameters** | lowercase | `a`, `b`, `ctx`, `req` |
| **Constructors** | PascalCase | `User(...)`, `Ok(...)`, `Error(...)` |
| **Opaque types** | PascalCase | `Email`, `PasswordHash` |

**Function Naming Patterns:**

| Pattern | Return Type | Example Use |
|---------|-------------|-------------|
| `get_*` | `Result(T, Error)` | `get_user(id) -> Result(User, DbError)` |
| `list_*` | `Result(List(T), Error)` | `list_users() -> Result(List(User), Nil)` |
| `create_*` | `Result(T, Error)` | `create_user(data) -> Result(User, ValidationError)` |
| `update_*` | `Result(T, Error)` | `update_user(id, data) -> Result(User, NotFound)` |
| `delete_*` | `Result(Nil, Error)` | `delete_user(id) -> Result(Nil, DbError)` |
| `is_*` | `Bool` | `is_eligible(donor) -> Bool` |
| `to_*` | `T` (encoded) | `to_json(user) -> Json` |
| `from_*` | `Result(T, Error)` | `from_json(json) -> Result(User, DecodeError)` |
| `try_*` | `Result(T, Error)` | `try_parse_email(raw) -> Result(Email, InvalidEmail)` |
| `validate_*` | `Result(Nil, ValidationError)` | `validate_password(pwd) -> Result(Nil, TooShort)` |

**Acronyms in Gleam:**
- HTTP, URL, ID, UUID: PascalCase in types (`HttpRequest`, `UserId`)
- snake_case in vars/functions (`http_client`, `user_id`)

## Functional Patterns

### Result Type & Error Handling

Use `Result(success, failure)` for all fallible operations. Never throw exceptions.

**Defining Errors:**
```gleam
pub type UserError {
  UserNotFound
  InvalidEmail(String)
  DuplicateUsername(String)
  ValidationFailed(List(String))
  DatabaseError(String)
}
```

**The `use` Expression:**
Flatten nested callbacks into sequential code:
```gleam
// Without `use` (nested)
result.try(get_user(id), fn(user) {
  result.try(validate_user(user), fn(_) {
    update_user(user)
  })
})

// With `use` (flat, sequential)
use user <- result.try(get_user(id))
use _ <- result.try(validate_user(user))
update_user(user)
```

**Error Propagation:**
```gleam
// In handler: map to HTTP response
pub fn get_user_handler(req: Request, ctx: Context) -> Response {
  use id <- result.try(parse_uuid(req))
  use user <- result.try(user_service.get(ctx.db, id))

  user
  |> user_to_json
  |> json.to_string_builder
  |> wisp.json_response(200)
}

// Map specific errors to status codes
fn map_error(err: UserError) -> Response {
  case err {
    UserNotFound -> wisp.not_found()
    InvalidEmail(_) -> wisp.bad_request()
    DatabaseError(_) -> wisp.internal_server_error()
  }
}
```

**Boolean Guards:**
Early returns for preconditions:
```gleam
pub fn create_user(data: CreateUserData) -> Result(User, UserError) {
  use <- bool.guard(data.age < 18, Error(TooYoung))
  use <- bool.guard(string.is_empty(data.email), Error(InvalidEmail("empty")))

  // Main logic here
  insert_user(data)
}
```

## Domain Modeling

### Custom Types (Algebraic Data Types)

Make illegal states unrepresentable:

```gleam
// Enum for fixed values
pub type BloodType {
  APositive
  ANegative
  BPositive
  BNegative
  ABPositive
  ABNegative
  OPositive
  ONegative
}

// Variant with data
pub type DonationStatus {
  Pending
  Scheduled(DateTime)
  Completed(DonationResult)
  Cancelled(String)  // Reason
}

// Opaque type for invariants
pub opaque type Email {
  Email(String)
}

pub fn parse_email(raw: String) -> Result(Email, String) {
  case string.contains(raw, "@") {
    True -> Ok(Email(string.lowercase(raw)))
    False -> Error("Invalid email format")
  }
}

pub fn to_string(email: Email) -> String {
  let Email(s) = email
  s
}
```

**Pattern Matching:**
The compiler ensures exhaustiveness:
```gleam
pub fn can_donate(blood_type: BloodType, recipient: BloodType) -> Bool {
  case blood_type, recipient {
    ONegative, _ -> True  // Universal donor
    _, OPositive -> True
    APositive, APositive | APositive, ABNegative -> True
    // Compiler error if we miss combinations!
  }
}
```

## Transaction Boundaries

Services own transactions. Use `pog` connection pooling with explicit transactions:

```gleam
// app/services/transaction.gleam
pub fn with_transaction(
  pool: pog.Connection,
  callback: fn(pog.Connection) -> Result(a, b),
) -> Result(a, b) {
  // Start transaction
  use _ <- result.try(pog.execute("BEGIN", pool, [], dynamic.dynamic))

  case callback(pool) {
    Ok(result) -> {
      // Commit on success
      let _ = pog.execute("COMMIT", pool, [], dynamic.dynamic)
      Ok(result)
    }
    Error(err) -> {
      // Rollback on error
      let _ = pog.execute("ROLLBACK", pool, [], dynamic.dynamic)
      Error(err)
    }
  }
}

// Usage in service
pub fn transfer_credits(
  ctx: Context,
  from: Uuid,
  to: Uuid,
  amount: Int,
) -> Result(Nil, TransactionError) {
  use conn <- transaction.with_transaction(ctx.db)

  use _ <- result.try(user_repo.debit(conn, from, amount))
  use _ <- result.try(user_repo.credit(conn, to, amount))

  Ok(Nil)
}
```

**Repository Signatures:**
```gleam
// Non-transactional
pub fn get_by_id(id: Uuid) -> pog.PreparedStatement(User)

// Transactional (accepts connection)
pub fn debit(
  conn: pog.Connection,
  user_id: Uuid,
  amount: Int,
) -> Result(Nil, DbError)
```

## Database (Pog + Squirrel)

### Connection Pool

```gleam
// app/db/connection.gleam
pub fn create_pool() -> Result(pog.Connection, String) {
  pog.default_config()
  |> pog.host("localhost")
  |> pog.database("myapp")
  |> pog.user("postgres")
  |> pog.password(env.get_string("DB_PASSWORD"))
  |> pog.pool_size(10)
  |> pog.connect()
}
```

### Squirrel Workflow

1. Write SQL in `sql/queries/users.sql`:
```sql
-- name: get_user_by_id
SELECT id, name, email, created_at
FROM users
WHERE id = $1;

-- name: create_user
INSERT INTO users (id, name, email)
VALUES ($1, $2, $3)
RETURNING id, name, email, created_at;
```

2. Run `squirrel` to generate `src/app/db/repo.gleam`
3. Wrap generated code in repositories:

```gleam
// app/db/user_repo.gleam
import app/db/repo.{get_user_by_id, create_user}

pub fn find_by_id(
  pool: pog.Connection,
  id: Uuid,
) -> Result(User, DbError) {
  case get_user_by_id(pool, id) {
    Ok([row]) -> Ok(row_to_user(row))
    Ok([]) -> Error(NotFound)
    Ok(_) -> Error(TooManyResults)
    Error(e) -> Error(DatabaseError(e))
  }
}

fn row_to_user(row: repo.GetUserByIdRow) -> User {
  User(
    id: row.id,
    name: row.name,
    email: row.email,
    created_at: row.created_at,
  )
}
```

## Wisp Handlers

### Handler Structure

```gleam
import wisp

pub fn create_user(req: Request, ctx: Context) -> Response {
  // 1. Method check
  use <- wisp.require_method(req, http.Post)

  // 2. Auth check
  use user <- result.try(auth_middleware.require_auth(req, ctx))

  // 3. Body parsing
  use body <- result.try(wisp.read_body(req, 1024 * 1024))  // 1MB limit
  use data <- result.try(json.parse(body, user_decoder()))

  // 4. Validation
  use valid_data <- result.try(validate_create_user(data))

  // 5. Business logic
  use new_user <- result.try(user_service.create(ctx.db, valid_data))

  // 6. Response
  new_user
  |> user_to_json
  |> json.to_string_builder
  |> wisp.json_response(201)
}
```

### Request Size Limits

Prevent DoS:
```gleam
// Limit body size to 1MB
use body <- result.try(wisp.read_body(req, 1024 * 1024))
```

## Actors (gleam_otp)

Use actors for:
- Caching (ETS-backed)
- Rate limiting counters
- Scheduled jobs
- Session storage

### GenServer Pattern

```gleam
import gleam/otp/actor
import gleam/erlang/process

pub type CacheMessage {
  Get(key: String, reply: process.Subject(Option(String)))
  Put(key: String, value: String)
  Clear
}

fn handle_message(
  msg: CacheMessage,
  state: Map(String, String),
) -> actor.Next(CacheMessage, Map(String, String)) {
  case msg {
    Get(key, reply) -> {
      process.send(reply, map.get(state, key))
      actor.continue(state)
    }
    Put(key, value) -> {
      actor.continue(map.insert(state, key, value))
    }
    Clear -> {
      actor.continue(map.new())
    }
  }
}

// Client API
pub fn start() -> Result(process.Subject(CacheMessage), StartError) {
  actor.start(map.new(), handle_message)
}

pub fn get(cache, key) {
  process.call(cache, Get(key, _), 1000)
}
```

## Code Quality Checklist

Before committing:

- [ ] Functions focused (<40 lines for logic, <60 for coordination)
- [ ] All `Result` types handled (no ignored errors with `let _ =`)
- [ ] No `todo` or `panic` in production paths
- [ ] Custom types for domain concepts (no stringly-typed)
- [ ] Opaque types for invariants (Email, PasswordHash)
- [ ] `use` expressions for clean Result chains
- [ ] Pattern matching exhaustive (compiler will warn)
- [ ] Request size limits set (prevent DoS)
- [ ] `gleam format` passes
- [ ] `gleam test` passes
- [ ] Squirrel queries regenerated if SQL changed
- [ ] No business logic in handlers
- [ ] Transaction boundaries in services (not repos)
- [ ] Actors have supervision (if using OTP)

## Security Defaults

- **Password Hashing:** Argon2id via `argon2_elixir` FFI (stores as binary)
- **Session/Auth:** JWT with short expiration (15min) + refresh tokens
- **IDs:** UUIDv7 (youid library) - time-sortable
- **SQL Injection:** Prevented by Squirrel parameterized queries
- **Input Validation:** Parse don't validate (Email opaque type)
- **HTTPS:** Enforce in production (Fly.io/Gigalixir handle this)
- **Secrets:** Use `envoy` or env vars, never commit secrets
- **Timing Attack Prevention:** Use `crypto.secure_compare` for tokens
